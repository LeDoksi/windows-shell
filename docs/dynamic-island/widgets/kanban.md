# Канбан — подготовка для Dynamic Island

2026-11-02. Только требования и проектирование; продуктовый код не меняется.

## Согласовано пользователем

- Быстрые действия внутри острова подходят как основа.
- При создании задачи нужен выбор её типа.
- Нужна возможность создать задачу в новом эпике.
- Отдельное окно полной доски тоже полностью перерабатываем: удобство,
  внешний вид и общий дизайн острова. Оно остаётся отдельным окном.
- Общий визуальный язык и motion распространяются на обе поверхности;
  это не перенос старой формы под новую оболочку.
- Удобный перевод в «Готово»: нынешняя область требует попадания в несколько
  пикселей. Конкретный способ действия ещё проектируется.
- Названия статусов соответствуют сайту; ожидание ответа пользователя обозначено
  как «Нужно от тебя». Пользователь сообщил, что сейчас вместо этого видит «Пауза».
- Визуальная группировка задач по эпикам; маленькой метки E7 недостаточно.
- Доступ к архиву.
- Архив — по нынешней модели сайта пользователя, с просмотром и восстановлением.
  Сверка исходников описана ниже; отдельное расширение на архив проектов и эпиков
  не утверждено.
- Явные типы «Задача / Баг / Долг» и их выбор в интерфейсе.
- Основной просмотр — все задачи по статусам, без обязательного выбора эпика.
  Группировка по эпикам должна помогать общему обзору, а не заменять его
  просмотром только одного эпика.
- Счётчик у значка показывает число задач «Нужно от тебя», а не «В работе».
  Пользователь сообщил о нынешнем значении 6 и пояснил, что этот показатель
  ему неинтересен. Отдельный постоянный индикатор в состоянии покоя не запрошен.
- Автоматическое событие перехода задачи в «Нужно от тебя» отклонено:
  во время работы канбан уже находится во внимании пользователя.

Компактный список «В работе» ранее предложен автором; отдельно его состав
и действия пользователь ещё не утвердил. В выборе смысла счётчика пользователь
отдал приоритет задачам «Нужно от тебя»; это не утверждает автоматически
новый состав быстрого списка.

## Текущая основа по исходникам

- `native/Shell/Kanban/KanbanFlyout.cs`: быстрое создание с выбором проекта
  и существующего эпика, отдельный вход в полную доску.
- `KanbanService.cs`, метод `Create`, вызывает `KanbanApi.Create`.
- `KanbanApi.cs`, метод `Create`: при создании передаётся фиксированное
  `type = "task"`; параметр эпика — идентификатор существующего эпика.
- `KanbanData.cs`: у задачи есть поле `Type`, у эпика — проект и заголовок.
- `KanbanWindow.cs`: самостоятельное окно полной доски.
- `Dock/Dock.Tail.cs`: бейдж и подсказка берут `KanbanService.Doing`;
  `KanbanService.cs` считает неархивные задачи со статусом `doing` в известных
  проектах. Таким образом, запрос относится к смыслу данных и подписи, а не
  только к отрисовке числа. Текущий счётчик при подготовке не менялся.
- `KanbanData.cs`: `waiting` подписан «Ждёт», `hold` — «Пауза»; это разные статусы.
  Требуется согласовать представление с сайтом, не подменять один статус другим.
- `KanbanWindow.cs`: на карточке есть короткая метка эпика, сверху фильтр по эпику;
  для бага выводится маленький значок. Это не решает запрос на визуальные группы
  и явное представление всех типов.
- `CardPanel.cs`: текущий заголовок различает `bug` («ошибка»), `chore` («дело»),
  остальные значения подписывает «задача». Сверка с сайтом 2026-11-07 (ниже):
  `chore` на сайте показан как «долг», `bug` — «баг».

Это подтверждает потребность изменить быстрый сценарий, а не только оформление.
Полный аудит поведения отдельного окна и поддерживаемых типов ещё предстоит.
Данные сервиса и пользовательские задачи в этой проверке не читались и не менялись.

## Предложение автора для обсуждения

В выборе эпика добавить «Новый эпик»: раскрыть ввод его названия внутри
острова, затем выбрать созданный эпик для текущей задачи. Сохранять набранные
поля задачи при переходе в создание эпика и обратно. Момент сохранения эпика,
обработка частичного успеха и отмены ещё не выбраны.

Для общего обзора предложить на эскизе колонки статусов с группами задач
по эпикам внутри колонок. У группы видно название эпика; обозначения одного
эпика согласованы между колонками. Задачи без эпика тоже видны.
Это гипотеза компоновки, не утверждённый пользователем макет.

Для нового счётчика сохранить отсутствие архивных задач в подсчёте и скрытие
числа при нуле; область подсчёта не расширять и не сужать без решения.
Ранее предложенное краткое событие острова, когда задача начинает требовать
ответа пользователя, отклонено. В набор событий его не включать.
