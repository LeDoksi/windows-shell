# Система виджетов

## Принцип

Виджет — **модуль в репозитории**, а не динамический плагин. Добавить виджет = попросить Claude, он пишет модуль, CI собирает новую версию. Это убирает целый класс проблем (песочница, совместимость API, безопасность чужого кода), и при этом добавлять виджеты по-прежнему быстро. Динамическую загрузку можно сделать позже, если появится потребность.

```text
widgets/
└── audio/
    ├── manifest.ts        # id, название, иконка, слоты, настройки по умолчанию
    ├── ui/                # React: компактный вид + flyout
    └── native/            # Rust: сервис с командами и событиями (если нужен)
```

## Контракт

```ts
export const audioWidget = defineWidget({
  id: "audio",
  name: "Звук",
  icon: "speaker",
  slots: ["dock", "launcher"],          // где может жить
  compact: AudioCompact,                // иконка/мини-вид в слоте
  flyout: AudioFlyout,                  // панель по клику
  settings: { defaults: { step: 2, showApps: true } },
  service: "audio",                     // Rust-сервис, к которому обращается
});
```

Rust-сторона — трейт `WidgetService`: `commands()` (вызовы из UI), `events()` (поток обновлений в UI), `start()/stop()` (сервис работает только пока виджет кому-то показан). Фронт обращается к сервису через типизированную обёртку `useService("audio")`, никаких сырых `invoke` в компонентах.

## Слоты (где живут виджеты)

| Слот | Вид | Когда |
|---|---|---|
| `dock` | Иконка в правой зоне дока (после разделителя, как ⚙ на концепте), клик → flyout над доком | MVP |
| `launcher` | Компактная кнопка справа в верхней панели рядом с 🔍 ＋ ⚙ | MVP |
| `desktop` | Карточка на рабочем столе под окнами (часы, заметки) | Позже: требует «прибить» окно к слою обоев (WorkerW), это отдельный риск |

Пользователь в настройках выбирает, какие виджеты в каком слоте и в каком порядке. В конфиге: `widgets: [{ id, slot, order, settings }]`.

## Первый виджет: Аудио

Всё через Windows Core Audio API (`windows` крейт), прецедент — открытый EarTrumpet.

### Компактный вид
- Иконка громкости, отражающая уровень и mute.
- Колесо мыши над иконкой — громкость ±2%. Средний клик — mute.

### Возможности и API

| Возможность | API | Статус API | Этап |
|---|---|---|---|
| Список устройств вывода/ввода, имена, горячее подключение | `IMMDeviceEnumerator`, `IMMNotificationClient` | Документировано | A1 |
| Громкость и mute устройства, синхронизация с системой | `IAudioEndpointVolume` + callback | Документировано | A1 |
| Пиковый уровень (индикатор) | `IAudioMeterInformation` | Документировано | A2 |
| Сменить устройство по умолчанию | `IPolicyConfig` | **Недокументировано**, стабильно с Win7 | A1 |
| Громкость и mute по приложениям | `IAudioSessionManager2`, `ISimpleAudioVolume` | Документировано | A2 |
| Микрофон: устройство, mute | те же API, `eCapture` | Документировано | A2 |
| Сейчас играет + play/pause/next | `GlobalSystemMediaTransportControlsSessionManager` (WinRT) | Документировано | A3 |
| Профили («Наушники 40%», «Колонки 70%»), хоткеи переключения | своя логика поверх A1 | — | A3 |
| Вывод конкретного приложения на другое устройство | `IAudioPolicyConfigFactory` | **Недокументировано**, менялось между сборками | A4, опционально |

Риски: недокументированные интерфейсы изолируем в одном модуле `audio::policy` с проверкой версии Windows; если вызов не удался, пункт в UI просто отключается.

## Следующие кандидаты

- Медиа-плеер (если не войдёт в аудио).
- Яркость мониторов (DDC/CI) и ночной режим.
- Буфер обмена (история).
- Быстрые переключатели: Wi-Fi/Bluetooth/режим питания.
- Системный монитор (CPU/RAM/GPU).
- Погода/календарь.
