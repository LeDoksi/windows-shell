# Windows Desktop Shell — MVP v2

## Идея

Создать небольшое Windows-приложение, которое превращает рабочий стол в чистую персональную оболочку поверх Windows.

Приложение состоит из двух основных элементов:

1. **Top Launcher** — компактная верхняя панель с категориями и плитками.
2. **Bottom Dock** — плавающий нижний Dock в духе macOS для запуска приложений и переключения между запущенными окнами.

Цель MVP — убрать большую часть ярлыков с рабочего стола и заменить их единым, красивым и удобным интерфейсом.

Пример:

```text
╭──────────────────────────────────────────────────────────────────────╮
│ 📁 Работа  📁 Проекты  📁 Личное  🎮 Игры  📥 Скачать  ⭐ Частое  🔍 ⚙ │
╰──────────────────────────────────────────────────────────────────────╯


                         ТВОИ ОБОИ


                  ╭──────────────────────────────╮
                  │ 🪟  🔍  💬  🎮  🌐  📁  ⚙️ │
                  ╰──────────────────────────────╯
                    ●        ●           ●
```

---

# 1. Стек

Использовать:

- Tauri 2.12
- React 19.3
- TypeScript
- Vite
- локальное хранение конфигурации в JSON
- Windows-first

Не использовать на MVP:

- backend;
- базу данных;
- аккаунты;
- авторизацию;
- облачное хранение;
- синхронизацию.

Приложение должно работать полностью локально.

---

# 2. Top Launcher

## Общая идея

Компактная панель находится у верхнего края экрана.

В обычном состоянии она скрыта.

При наведении мыши к верхнему краю появляется:

```text
╭────────────────────────────────────────────────────────────╮
│ 📁 Работа  📁 Проекты  📁 Личное  🎮 Игры  ⭐ Частое  🔍 ⚙ │
╰────────────────────────────────────────────────────────────╯
```

Панель должна:

- быть прозрачной/полупрозрачной;
- иметь blur;
- иметь скруглённые углы;
- находиться поверх остальных окон;
- автоматически скрываться;
- появляться при наведении;
- иметь возможность закрепления;
- поддерживать выбор монитора.

---

# 3. Категории

Начальные категории:

- Работа
- Проекты
- Личное
- Игры
- Скачать
- Частое

Пользователь может:

- создавать категории;
- удалять категории;
- переименовывать категории;
- менять иконку;
- менять порядок категорий.

Категории не обязаны соответствовать реальным папкам Windows.

Они являются логическими коллекциями ссылок на объекты.

---

# 4. Окно категории

При нажатии на категорию открывается отдельное компактное окно с плитками.

Пример:

```text
╭──────────────────────────────────────────────╮
│ 📁 Работа                         🔍       ✕ │
│                                              │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐      │
│ │    📊    │ │    💬    │ │    🌐    │      │
│ │          │ │          │ │          │      │
│ │  Excel   │ │  Teams   │ │   WFM    │      │
│ │Приложение│ │Приложение│ │   Сайт   │      │
│ └──────────┘ └──────────┘ └──────────┘      │
│                                              │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐      │
│ │    📁    │ │    📄    │ │    ＋     │      │
│ │  Отчёты  │ │Planning  │ │ Добавить │      │
│ └──────────┘ └──────────┘ └──────────┘      │
│                                              │
│  📂 Открыть исходную папку                  │
╰──────────────────────────────────────────────╯
```

Окно должно поддерживать:

- поиск внутри категории;
- сетку плиток;
- drag & drop;
- контекстное меню;
- добавление новых элементов;
- изменение порядка плиток.

---

# 5. Плитки

Поддерживаемые типы:

- файл;
- папка;
- приложение;
- URL.

Каждая плитка содержит:

- иконку;
- название;
- тип объекта или краткое описание.

При клике:

- файл → открыть стандартным приложением Windows;
- папка → открыть в Windows Explorer;
- приложение → запустить;
- URL → открыть стандартным браузером.

---

# 6. Добавление объектов

Поддержать два способа.

## Способ 1 — кнопка "+"

Нажатие на `Добавить`:

```text
Что добавить?

📁 Папку
📄 Файл
💻 Приложение
🌐 Ссылку
```

После выбора пользователь указывает нужный объект.

## Способ 2 — Drag & Drop

Объект из Windows Explorer можно перетащить прямо на категорию или в окно категории.

По умолчанию приложение только сохраняет ссылку на объект.

Оно НЕ должно автоматически:

- перемещать файл;
- копировать файл;
- переименовывать файл;
- удалять файл.

---

# 7. Перетаскивание плиток

Плитки можно:

- перемещать внутри категории;
- менять их порядок;
- переносить между категориями.

Порядок должен сохраняться после перезапуска.

---

# 8. Контекстное меню плитки

ПКМ по плитке:

```text
┌──────────────────────────┐
│ Открыть                  │
│ Открыть расположение     │
│                          │
│ Переименовать             │
│ Переместить в...          │
│                          │
│ Удалить из панели         │
└──────────────────────────┘
```

Критически важно:

**«Удалить из панели» никогда не должно удалять реальный объект пользователя.**

Удаляется только запись из конфигурации приложения.

---

# 9. Bottom Dock

## Общая идея

Нижняя панель — отдельное приложение/окно, а не визуальная часть Windows Taskbar.

Она должна выглядеть как современный macOS-подобный Dock:

```text
                    ╭───────────────────────────────╮
                    │ 🪟  🔍  💬  🎮  🌐  📁  ⚙️ │
                    ╰───────────────────────────────╯
```

Dock должен:

- быть плавающим;
- быть центрированным;
- иметь прозрачный/полупрозрачный фон;
- использовать blur;
- иметь скругления;
- не растягиваться на всю ширину экрана;
- располагаться над рабочим столом;
- автоматически скрываться;
- появляться при наведении к нижнему краю.

---

# 10. Внешний вид Dock

Стиль:

- современный;
- минималистичный;
- тёмный translucent/glass;
- мягкие тени;
- аккуратные скругления;
- крупные иконки;
- минимум визуального шума.

Не копировать интерфейс macOS буквально.

Нужно передать ощущение:

- floating;
- premium;
- clean;
- responsive.

---

# 11. Magnification

При наведении курсора на иконки Dock применяется эффект увеличения.

Например:

```text
      🟦  🟩  🔵  🟥  🟪
                ↑
             курсор
```

При наведении:

```text
    🟦  🟩  🔵🔵  🟥  🟪
             ↑
        увеличилась
```

Соседние иконки могут слегка увеличиваться тоже.

Анимация должна быть плавной и быстрой.

---

# 12. Запуск и переключение приложений

Dock должен понимать состояние приложений.

## Если приложение не запущено

Клик:

```text
Chrome
  ↓
запустить Chrome
```

## Если приложение уже запущено

Клик:

```text
Chrome
  ↓
переключиться на окно Chrome
```

Поддержать как минимум:

- запуск;
- фокусировку;
- сворачивание;
- восстановление окна.

---

# 13. Индикатор запущенного приложения

Под запущенными приложениями показывать небольшой индикатор:

```text
🌐    💬    🎮    📁
 ●     ●     ●     ●
```

Незапущенные приложения индикатора не имеют.

---

# 14. Несколько окон одного приложения

Если у приложения открыто несколько окон, допускается простой popup со списком окон:

```text
╭────────────────────────╮
│ ChatGPT                │
│ YouTube                │
│ Claude                 │
╰────────────────────────╯
```

Для MVP достаточно:

- отображать список окон;
- при выборе переключаться на соответствующее окно.

Сложные live-preview и предпросмотры окон в MVP не нужны.

---

# 15. Закрепление приложений

ПКМ по элементу Dock:

```text
┌──────────────────────────┐
│ Открыть                  │
│ Новое окно               │
│ ──────────────────────── │
│ Закрепить в Dock         │
│ Удалить из Dock          │
│ ──────────────────────── │
│ Открыть расположение     │
└──────────────────────────┘
```

В Dock должны существовать:

1. закреплённые приложения;
2. временно отображаемые запущенные приложения.

Незапущенное незакреплённое приложение исчезает из Dock после закрытия.

---

# 16. System Tray

Не пытаться в MVP полностью заменить или перерисовать системный tray Windows.

Сохраняется отдельная системная область:

```text
                         Wi-Fi  🔊  🔋  12:22
```

Она должна оставаться функциональной.

Наш Dock визуально согласуется с системной областью, но технически это отдельные компоненты.

---

# 17. Windows Taskbar / Windhawk

Windhawk не является частью основного приложения.

Он используется как интеграционный слой для того, чтобы штатный Windows Taskbar визуально не мешал нашему Dock.

Цель Windhawk-конфигурации:

- убрать/сделать прозрачным фон штатного Taskbar;
- минимизировать стандартную визуальную область;
- убрать ненужные отступы;
- сохранить необходимую системную функциональность;
- не пытаться реализовать весь Dock средствами Windhawk.

Архитектура:

```text
Windows Taskbar
      ↓
   Windhawk
      ↓
минимально заметный
системный слой


      OUR DOCK
          ↓
   красивый floating UI
```

На ранних этапах разработки Windhawk не трогать.

Сначала реализовать собственный Dock, затем заниматься интеграцией.


```text
╭─────────────────────────────────────────╮

├─────────────────────────────────────────┤
│ 📊 Planning.xlsx           Работа       │

│ 📁 Planning                 Личное       │
```

Поиск выполняется по объектам, зарегистрированным в приложении:

- Tile Grid;
- Bottom Dock;

Подключить:

## Этап 3 — запуск объектов

Подключить:

Подключить:

# 24. Что НЕ делать в MVP

Не реализовывать:

- полноценный файловый менеджер;
- поиск по всему диску;
- облачную синхронизацию;
- авторизацию;
- backend;
- виртуальные рабочие столы;
- полноценную замену Start Menu;
- полную замену системного tray;
- сложные live-preview окон;
- автоматическую классификацию файлов;
- автоматическое перемещение файлов;
- плагины;
- виджеты;
- мобильные версии;
- темы и marketplace тем;
- поддержку Windows 10.

# 27. Критерии готовности MVP

MVP считается готовым, когда пользователь может:

1. Запустить приложение вместе с Windows.
2. Навести мышь к верхнему краю и открыть Top Launcher.
3. Открыть категорию.
4. Увидеть сетку плиток.
5. Запустить файл, папку, приложение или URL.
6. Добавить объект через кнопку "+".
7. Добавить объект через Drag & Drop.
8. Перетащить плитку и изменить её порядок.
9. Перенести плитку в другую категорию.
10. Открыть контекстное меню.
11. Удалить запись из панели без удаления реального файла.
12. Открыть глобальный поиск через Ctrl + Space.
13. Использовать Bottom Dock для запуска приложений.
14. Переключаться на уже открытое приложение через Dock.
15. Видеть индикатор запущенных приложений.
16. Видеть эффект увеличения иконок при наведении.
17. Настроить размер/прозрачность/автоскрытие.
18. Перезапустить приложение и сохранить все настройки.
19. Использовать приложение вместе с обычными Windows-программами без необходимости постоянно держать открытый отдельный интерфейс.

---

# 28. Правило разработки

Разрабатывать поэтапно.

После каждого этапа приложение должно оставаться запускаемым и рабочим.

Не усложнять архитектуру заранее.

Не создавать backend без необходимости.

Не добавлять функции, которых нет в MVP.

Сначала добиться хорошего UX и визуального качества, затем наращивать Windows integration.

Главный приоритет:

**приложение должно ощущаться как цельная современная оболочка, а не как набор разрозненных Windows-хаков.**
