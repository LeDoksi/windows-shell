# Оболочка на WinUI 3 (WSH-E13 → WSH-E14)

Новая версия оболочки на родной технологии Windows 11 (WinUI 3, C#). В WSH-E13 это был прототип
для сравнения, в WSH-E14 на неё переехало всё, что было в версии на Tauri. Поведение описано в
`behaviour-spec.md` (файлы проекта), проверка идёт по его спискам «Как должно быть».

Что есть:

- **Док на каждом мониторе** (раздел 1 и 9): кнопка Пуска, закреплённые и запущенные программы со
  всех мониторов, точки, увеличение волной, подписи, список окон с живыми миниатюрами, просьба
  внимания (иконка подпрыгивает, точка оранжевая), «Не найдено». Перетаскивание: порядок, закрепить
  запущенное, «Убрать» вверх, Esc, ярлыки и exe из Проводника, файл на иконку программы.
  Хвост: звук и часы на мониторе хвоста, на остальных только часы.
- **Автоскрытие и закрепление** (1.6, 4, 9): выезд за 150 мс у края, уезд через 600 мс, не уезжает,
  пока открыто его окошко или тащат иконку; над полноэкранной игрой не выезжает; край, за которым
  соседний монитор, не считается. «Закрепить док / панель» резервирует место (AppBar).
- **Верхняя панель** (раздел 4) на любом мониторе: пилюли категорий, наведение переключает открытую,
  правый клик — переименовать, цвет, удалить; перетаскивание пилюль; ＋ новая категория; ⚙ настройки
  виджетов; «Сейчас играет». **Окно категории**: плитки, фильтр печатью, стрелки и Enter, меню плитки,
  перетаскивание (порядок, на другую пилюлю, на док), файлы из Проводника.
- **Меню трея** (раздел 5): настройки виджетов, монитор хвоста, закрепление, «Стекло / Тонировка»,
  перезапуск, выход.
- **Виджеты**: «Звук» (окошко, профили, горячие клавиши), «Сейчас играет», настройки виджетов.

Пока нет (следующие этапы): свой Пуск и Win+X (WSH-E15, кнопка открывает родной Пуск), окно настроек и
автозапуск (WSH-E8), скрытие панели задач Windows, свой трей, сеть, батарея (WSH-E9).

## Данные

`%APPDATA%\WindowsShellNative\`:

- `config.json` — конфиг в той же схеме, что у версии на Tauri. Первый запуск берёт всё из
  `%APPDATA%\com.ledoksi.windowsshell\config.json` (его не трогаем), а закреплённое в доке — из
  `prototype.json` прототипа, если он есть. Рядом `config.json.bak`; испорченный файл откладывается в
  `config.broken.json`.
- `shortcuts\` — копии ярлыков, брошенных из Проводника.
- `log.txt` — журнал запуска и ошибок.

## Сборка

Нужен .NET 8 SDK. Готовая сборка лежит в артефакте CI `windows-shell-native-<коммит>`.

```
dotnet publish native/Shell/Shell.csproj -c Release -r win-x64 -o native/publish
native\publish\WindowsShellNative.exe
```

В Linux-контейнере C# проверяется так (шаги, которым нужен Windows, падают, это нормально;
важно, что нет `error CS`):

```
dotnet build native/Shell/Shell.csproj -p:WindowsAppSDKSelfContained=false 2>&1 | grep "error CS"
```

## Как устроено

- `App.cs` → `ShellHost.cs` — запуск; доки и панели по мониторам, трей, горячие клавиши.
  `Services.cs` — общее для всех окон: конфиг, трекер окон, звук, медиа, иконки, общие окошки.
- `Dock/Dock.cs` — два окна: снизу таблетка со стеклом, сверху прозрачное окно с иконками. Каждый
  кадр двигаются только визуалы (`Translation`/`Scale`), без раскладки. Пока курсор не над доком,
  полоса ловит мышь только на таблетке (`SetWindowRgn`).
- `Panel/` — верхняя панель, окно категории, поле названия, «Сейчас играет», настройки виджетов.
- `Ui/Bars.cs` — автоскрытие и AppBar: фоновый поток опрашивает курсор, в поток интерфейса приходят
  только перемены. `Ui/Popup.cs` — всплывающие окошки: одно открыто, повторный клик закрывает, клик
  мимо закрывает и срабатывает, фокус возвращается; меню внутри окошка (плитка) не закрывает его.
- `Native/` — Win32: окно сообщений (трей, хоткеи, «просит внимания», мониторы, сон), мониторы, хоткеи.
- `Apps/`, `Audio/`, `Media/` — трекер окон, запуск, иконки, Core Audio, «Сейчас играет» (WinRT).
